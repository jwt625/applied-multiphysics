## 1. Plan (written 2026-11-06 19:08 PST, before coding)

### 1.1 Adapter `src/provider/openai-compatible.ts`

- `createOpenAICompatibleAdapter({keys, fetch, baseURL, model, maxTokens, price, reasoning, thinking, reasoningEffort, jsonRetries})` implementing `ProviderAdapter`. `fetch` is injected by the host (the package itself still makes no network call; DevLog-012 gate 3 source scan stays true for `src/`). Non-streaming (`stream: false`); `onText` gets the whole text once. Streaming is optional and not built.
- `DEEPSEEK_PRESET`: baseURL `https://api.deepseek.com`, model `deepseek-flash`, prices peak and off-peak with the source URL and access date, peak windows, `reasoning: 'replay'`, `thinking: enabled`, `reasoning_effort: high`.
- Wire: `POST {baseURL}/chat/completions`, `Authorization: Bearer <key>`, body `model, messages, tools, tool_choice: auto, max_tokens, stream: false, thinking, reasoning_effort`. `system` first. Tools as `{type: function, function: {name, description, parameters}}`. A neutral user message with `tool_result` blocks becomes one `tool` message per result (images as `image_url` data-URL parts), then a `user` message for any text. Assistant messages from this adapter replay the raw message (`content`, `reasoning_content`, `tool_calls`) unchanged; others are rebuilt from blocks.
- `reasoning_content`: per the docs, with `tools` every previous assistant message's `reasoning_content` goes back (else 400). Every request of the loop carries `tools`, so the adapter replays it always (`reasoning: 'replay'`); `'drop'` for providers that reject the field. Inside the neutral history it travels as an `opaque` block (kind `reasoning_content`), which keeps the loop's "opaque-only message is not kept" rule.
- Response: text -> text block; `tool_calls` -> `tool_use` (arguments parsed; unparseable JSON re-issues the request at most `jsonRetries` (2) times, then `invalid_tool_input`; a model-made invalid call cannot be fed back because Chat Completions rejects tool calls it did not generate, s.0). `finish_reason`: `stop` -> end_turn, `tool_calls` -> tool_use, `length` -> max_tokens, `content_filter` -> refusal (category `content_filter`), `insufficient_system_resource` -> server error, others -> other.
- Usage: `inputTokens` = cache-miss tokens, `cacheReadTokens` = cache-hit tokens, `outputTokens` = `completion_tokens` (includes reasoning), new optional `reasoningTokens` on the response. Cost through the loop's existing formula (miss x input + hit x cacheRead + output x output). `price()` default peak (upper bound of what is billed); `pricing: 'time-of-use'` prices by the UTC hour (holidays ignored, so still an upper bound).
- Errors: 401/403 auth, 402 new kind `billing`, 400/422 bad_request, 429 rate_limit, 5xx server, fetch `TypeError` network, `AbortError` aborted. Messages: provider error text, redacted (the key itself, `Bearer ...`, `sk-...` shapes) and cut to 500 chars.
- `wireProblems` fix: raw content is read as blocks only for `anthropic` raw messages; other providers are checked through their neutral blocks.

### 1.3 Live trial `eval/live/run-deepseek.ts`

- Launcher reads the key file (path built from `os.homedir()`), puts the key in a memory-only `KeyStore`, builds the DeepSeek adapter with `globalThis.fetch`. The key never goes to stdout, logs or files.
- `TrialProvider` (wrapper): records every request for the checkers (same role as `ScriptedProvider.requests`), wire-checks each one, records per call (ms, finish, prompt / cache-hit / completion / reasoning tokens, tool names), and enforces the hard caps before each call: at most 12 model calls per task, USD 0.20 per task, USD 2.00 for the whole trial, all at peak rates (upper bound) with the worst case of the next call reserved (input bytes/4 at the miss price + `max_tokens` x output price). A refused call throws a `ProviderError`; the trial stops launching tasks once the total cap is reached.
- `runTask` gains a `provider` option (recording interface instead of `ScriptedProvider`); fault tasks keep their fault: T21 (refusal) and T23 (rate-limit error) get the scripted step at call 1, everything else from the live model. T22 (malformed tool input) cannot be injected: Chat Completions rejects tool calls the model did not make (s.0); it runs live as is.
- Agent budget per task: `maxModelCalls` min(12, task), `maxCostUSD` 0.20.
- Pilot: T01 (edit + repair + FE run) and T07 (injection). Look, then the full 27 if the pilot is not a systematic failure.
- Output: `logs/L9b-deepseek-<stamp>.jsonl` (one line per task: pass, failures, calls, tokens, cost at peak and time-of-use, wall time, tool sequence, answer head; then a summary line) and a console log. Table and failure patterns in s.4.
