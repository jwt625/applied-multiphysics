## 7. Digitization protocol (figure-only values)

Rule: a value read from a figure enters a case only through `validation/b/digitize.py` with a spec file under
`validation/b/digitize_specs/`, and carries its standard uncertainty. No eyeballed numbers.

1. Spec records: citation, licence, locator, source path (relative to the repo root) + sha256, page, dpi, crop, per
   panel the approximate box, expected tick labels, axis scale, curve RGB + tolerance, exclusion boxes (legends),
   sample x positions.
2. Render the page with `pdftoppm` at the spec dpi (300 for the pilot); crop.
3. Frame lines: darkest column / row per half of the panel box, widened to the full stroke; inner edges kept.
   Only neutral (low-chroma) pixels count as ink, so coloured curves never become frame or ticks.
4. Ticks: inward tick marks found as dark runs of length `tick_len_px` next to the frame. Labels sitting on a frame
   line (`*_edge_ticks`) use the stroke centre.
5. Tick labels: tesseract OCR (digits) of the label strip (x) or one window per tick (y). OCR values must be in the
   expected label list; unmatched ticks get the expected label that the first fit predicts within 5 % of a label
   step (`labels_from: ocr+N_inferred_from_fit`). If OCR fails entirely, labels are assigned in order only when the
   tick and label counts are equal (`labels_from: spec_order`); otherwise the run stops.
6. Calibration: least squares value = a + b px per axis; u_cal = sqrt(fit RMS (n - 2 dof)^2 + (|b| 0.5 px / sqrt 3)^2).
7. Curve: RGB distance < tol inside the frame; per pixel column the mean row and stroke thickness.
8. Uncertainty (k = 1): u_y = sqrt(|b_y|^2 (u_q^2 + u_line^2) + u_cal,y^2), u_q = 0.5 px / sqrt 3, u_line =
   (thickness / 2) / sqrt 3; at a requested x the x uncertainty enters through the local slope. U = 2 u is the
   tolerance floor for any target built on a digitized value.
9. Outputs: JSON (`amp-digitize/0`: spec, source sha256, calibration pairs, OCR readings, per-column points with u,
   samples, ISO timestamp) and an overlay PNG (frame, calibration ticks, extracted points, sample markers) that a
   person checks before the value is used. Overlays stay in `outputs/` (gitignored); the JSON goes to
   `validation/b/digitized/`.
10. Limitations found in the pilot: where two curves overlap, the lower one is partly hidden, its stroke looks
    thinner and u_line is underestimated (Z_m measured at 40 GHz: u = 0.068 ohm vs pixel size 0.136 ohm). Use samples
    away from overlaps, or take the pixel size as the floor. Log axes: calibration supported, uncertainty
    propagation not implemented (the script stops).

Self-test (`--selftest`): matplotlib figure of y = 1.2 + 0.035 x + 0.4 sin(x / 9), x 2-67, y 0-6, 1000 x 600 px;
digitized at 5 x positions; all within U; mean bias +0.008 (about 0.6 px), inside U.

Pilot: Arab Juneghani et al. 2022, Fig. 4 (p.4), CC BY 4.0, read in place from the EO atlas reference PDF (not
