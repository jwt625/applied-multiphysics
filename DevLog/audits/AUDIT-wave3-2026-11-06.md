### Major

**M1. DG0 smoothing changes the shown extremes; the colorbar note then contradicts the colorbar.**
- Files: `apps/web/src/lib/post/post.worker.ts:124-137`, `apps/web/src/lib/gfx/Graphics.svelte:184` and `:321`, `apps/web/src/lib/post/field2d.ts:217`.
- What happens: with smoothing on (the default), the range and the peak come from lattice values of the recovered field. The recovered field is the area-weighted mean of the cells around each corner, so it is lower than the per-cell FE extremes. The eigenmode normalization still divides by the raw `max |field|` (line 184), and the colorbar note still says "normalized eigenmode: max |Ey| = 1".
- Failure scenario: open si-strip-te0, Compute, select field Ey. The colorbar reads -0.854 to 0.854 while its note says max |Ey| = 1. Raw mode reads -1 to 1.
- The peak marker tip says "largest |Ey| on the mesh" but marks the smoothed maximum. The probe and Table show the exact cell values, so they exceed the colorbar end.
- `ElementCoef.note` ("per-cell values recovered ...") is computed in the worker but never shown anywhere.
- Evidence:
  - Node: solved si-strip-te0 at hFactor 1 (4529 tri6).
    - Ey: exact per-cell range [-0.4205, 0.3646]; smoothed lattice range [-0.3592, 0.2892]; max ratio 0.79.
    - normE: ratio 0.995.
  - Browser screenshots (smooth vs Raw, zoomed on the core) show colorbar ends 0.854 vs 1.
- Every em-modes field is DG0, so every mode-solver view is affected.

**m2. The coefficient texture has no MAX_TEXTURE_SIZE guard.**
- Files: `apps/web/src/lib/post/field2d.ts:220` (`COEF_WIDTH = 4096`), `apps/web/src/lib/gfx/renderer2d.ts:374` and `:494`.
- On a device with MAX_TEXTURE_SIZE 2048 (the WebGL2 minimum), the 4096-wide RGBA32F upload fails. texelFetch then returns 0 and the field is drawn as the constant `b`, with no error and no fallback to `values`.
- Height is safe: the largest 2D mesh the mesher allows (1e6 P1 vertices, about 2e6 triangles, K = 5) needs 2442 rows, under 4096. SwiftShader reports 8192.
- Practical risk is low. A `getParameter(MAX_TEXTURE_SIZE)` check with a fallback to `uCoefOn = 0` closes it.

**m3. The Raw toggle covers 2D only.**
- Files: `apps/web/src/lib/gfx/viewer3d.ts:102` (`p2: true` always), `apps/web/src/lib/gfx/Graphics.svelte:648` (Raw button only when `m2 && !rev`).
- 3D tet10 surfaces always use the per-fragment P2 basis. The old piecewise-linear 3D path cannot be restored.
- The 3D colour range comes from vertex values, so P2 overshoot between nodes saturates at the colorbar ends.

**m4. `p2Attrs` reallocates on every value update.**
- File: `apps/web/src/lib/gfx/viewer3d.ts:148` and `:155`.
- Each `setValues` creates three new `Float32Array(3n)` and three new BufferAttributes, plus a GPU upload. This happens on every step of a transient 3D animation. Correct, but it churns memory.

**m5. Sweep memory grows linearly with the number of points.**
- File: `apps/web/src/lib/workbench/session.svelte.ts` (computeSweep).

- Measured JS heap: 37 MB at open, 70 MB after 2 points, 91 MB after all 7 points of si-rib-waveguide (largest point 328754 DOF). Acceptable at this size; a 4-axis sweep would scale with n^4.
