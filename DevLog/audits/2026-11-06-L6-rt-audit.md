## 3. Physics review (no defect found)

- **LBM.**
  - TRT: omega- = 1/(1/2 + Lambda/(tau+ - 1/2)). Even/odd split with Guo forcing (even w(9 cu cf - 3 u.F), odd 3 w c.F, prefactors 1 - omega/2) and u = (j + F/2)/rho are correct.
  - Halfway bounce-back in pull form is correct.
  - Zou-He inlet in deviation form: the weights of the known populations sum to 1, so rho = (1 + sum g)/(1 - u). Correct.
  - Outlet: rho = 1 equilibrium plus the post-collision non-equilibrium part of the outlet-column cell along the link. This consistently approximates the post-collision state of the virtual node outside the domain. It is a variant, not Guo's textbook NEE (see M8), and the results are equivalent (section 2).
  - Momentum exchange: 2 f* c_k over fluid-to-obstacle links, from the post-collision state, with full f = g + w. Correct.
  - Units:
    - nu = U_mean D/Re in lattice units; tau = 3 nu + 1/2.
    - Ma = u_max sqrt(3), against cs = 1/sqrt(3).
    - dt = dx u_lat/U_phys.
    - Vorticity scale = velScale/dx.
    - c_D = F/(0.5 U_mean^2 D), with rho = 1.
    - St = (1/T) D/U_mean.
    - All correct. DFG geometry mapping: inlet node at x = 0, walls midway at j = 0.5 and ny - 1.5, cylinder centre (2 nD, 0.5 + 2 nD). Correct.
- **FDTD.**
  - Normalised H' = eta0 H gives update factor S for both H and E, and S/eps_r for dielectrics. Correct.
  - Courant default 0.5, validated in (0, 1/sqrt(2)]. Correct.
  - CPML (Roden-Gedney):
    - b = exp(-S(sigma_hat/kappa + alpha_hat)) and c = sigma/(sigma kappa + kappa^2 alpha)(b - 1) follow from sigma dt/eps0 = sigma_hat S.
    - sigma_opt = 0.8(m + 1)/(eta0 dx); polynomial grading m = 3.
    - E profile at integer nodes, H profile at half nodes. PEC backing.
    - All correct.
  - Theoretical continuous reflection at 10 cells: exp(-1.6 N) = -139 dB. The measured -91 dB is the discretisation floor, which is plausible.
  - Soft source: Ez += src w(t). Amplitude is therefore in a.u. (see M13). Ricker t0 = 1.5/f; w(t = 0) is about 3e-10.
- **Gray-Scott.**
  - The 5-point Laplacian divided by dx^2, explicit Euler, and the equation form all match The Well's equations.
  - Reaction stiffness at dt 1: (f + k) dt <= 0.16 for the six sets. Stable.

## 4. Findings

### Blocking

None.

### Significant

**S1. The gate harness never fails.**
- Evidence:
  - `scripts/gates.ts` writes numbers and always exits 0.
  - Only `strouhal` and `gsPattern` rows carry `pass`.
  - Gate 1 and 1b have no numeric threshold in DevLog-005 s.3 ("L2 + convergence"; "profile vs the parabola").
  - These section 3 criteria are not asserted anywhere: gate 3 at 80^2 / 2000 steps; gate 4 on the GPU; gate 5 "< 1 % at N = 32 and about N^-2"; gate 6 at N = 1000 vs f64; gate 8 FDTD.
  - `node --test` asserts reduced versions only (40^2 / 600 steps, CPU cavity at N = 16, GS at 64^2 / 3000 steps).
  - "All gates pass" in DevLog-005 s.5/s.9 rests on reading the JSON by eye.
- Fix:
  - Compute `pass` per row from the s.3 thresholds, add `allPass`, and set `process.exitCode = 1` on any failure.
  - Write numeric thresholds for gates 1 and 1b into DevLog-005 before the next run, for example:
    - TRT f64 L2 < 1e-12;
    - BGK order 2 +- 0.05;
    - GPU TRT < 1e-4;
    - 1b L2shape < 1e-3.
  - Label these as new thresholds, not tuned ones.
  - Expose the same `pass` fields to L8.

**S2. The Node GPU path hides failures (`src/node-gpu.ts`, `src/gpu.ts`).**
- The three workarounds are safe:
  - keeping the GPU instance, adapter and device reachable costs nothing;
  - synchronous `createComputePipeline` inside a validation error scope throws on bad WGSL (verified: "Error while parsing WGSL ... expected ')'");
  - avoiding `getCompilationInfo` is fine.
- The surrounding error handling hides failures. Probe `scripts/dawn.ts` (auditor):
  - After `dispose()`, `GrayScott.step(10)` produced only a `console.error` from the `uncapturederror` listener; nothing threw.
  - `readback("v")` then returned 4096 zeros without error.
- Other paths:
  - `nodeGpu()` catches every exception (missing module, no adapter, device failure) and returns null. The 5 GPU tests are then "skipped", `pnpm test` stays green, and the gate JSON silently omits all GPU sections.
  - `device.lost` is not observed in Node.
  - The error scope in `pipeline()` is `validation` only. Out-of-memory and internal errors from large `createBuffer` calls (192 MiB in the bench) are not scoped.
- The current gates fail on zero data only incidentally: NaN propagates in the Strouhal, dispersion and CPML ratios, and the cavity peak lands at the band edge.
- Fix:
  - Count uncaptured errors in `nodeGpu` (export `gpuErrors()`) and assert zero after each gate and test.
  - Push `validation`, `out-of-memory` and `internal` scopes around `init()` allocations and pipeline creation.
  - Reject pending work on `device.lost`.
  - Add `AMP_REQUIRE_GPU=1` (set on this machine and in L8 runs) to turn skip into fail.
  - Make `gates.ts` exit non-zero when the GPU is missing unless `--cpu-only` is given.

**S3. The demo is unusable at 390 px, and the field aspect is distorted there.**
- Evidence (headless Chrome 390 x 844 at 3x, all three kernels):
  - `document.scrollWidth` is 1039-1089 px against a 390 px viewport. The body grid is a fixed `272px 1fr` with `overflow: hidden`, so content is cut off, not scrollable.
  - The canvas is 66 x 66 px for every kernel. `layout()` clamps width and height to 64 px independently, so the 881 x 166 LBM channel is drawn as a square: the cylinder becomes an ellipse and the colours no longer map to geometry.
  - The status line and footer are cut off.
- Desktop (1600 x 900) is good (see section 5).
- Fix:
  - Below about 700 px, use a single column: canvas at full width on top, a horizontal colorbar under it, and the parameter panel below it, collapsible.
  - Derive the scale from the available width only and never clamp the axes independently. Keep nx:ny exactly.
  - Wrap the status line or move it into a tooltip.

**S4. Hero gate coverage is short of DevLog-001 (disclosed in DevLog-005 O1/O3, not yet tracked as a ship blocker).**
- H9 (real-time tier) vs FL-04 bounds (R3: c_D,max 3.22-3.24, c_L,max 0.99-1.01, St 0.295-0.305):
  - St passes at every resolution.
  - c_D,max fails: 3.41-3.58 (+5.9 % at D 60, +9.5 % at D 10, reproduced independently in section 2).
  - c_L,max fails: 0.92-1.22.
  - The St band (+-1.7 %) passes even BGK, D = 10 cells and both Mach numbers, so it barely discriminates.
- H12:
  - No dataset gate (TR-03 VRMSE, O3) and no convergence study (dt and dx refinement). DevLog-001 s.6: "a hero ships only with at least one passing eval gate and a convergence study". The pattern-class gate tests The Well's set names, not The Well's data.
  - [est] The demo's Spots spacing is about 7 cells (from the screenshot: about 70 spots across 8 model units at dx = 1/64). At that wavelength the 5-point Laplacian underestimates k^2 by about (k dx)^2/12, roughly 7 %. Explicit Euler at dt 1 against reaction time scales of about 1/(f + k), 6-15 s, adds an O(dt) error. A VRMSE match to the ETDRK4 spectral frames is therefore not expected.
- H13: the hero table plans "RF-04 dipole trend; AC-01 duct". DevLog-005 substitutes analytic gates (dispersion, CPML, cavity with N^-2 convergence). These are sound, but the substitution is not recorded as a plan change.
- Fix:
  - Show the per-hero gate status in the demo next to the `fidelity: realtime` badge, for example "St pass; c_D, c_L fail FL-04". Missing evidence shows as unavailable (guideline).
  - Add a Gray-Scott convergence study (dt 1 / 0.5 / 0.25; dx halved) and a structural gate against The Well frames, for example the peak wavelength of the radially averaged power spectrum within a stated tolerance.
  - Record the H13 gate substitution with the coordinator.
  - O1 (Bouzidi interpolated bounce-back, lower Mach) remains the fix for the H9 forces.

### Minor

**M1. The double-slit preset is at the slit cutoff.**
- PEC rows at j = 160 and 175 (and 225 and 240) leave 15 mm openings = lambda0/2 at 10 GHz.
- For TMz, Ez vanishes on the slit walls, so the lowest slit mode has f_c = c0/(2w) = 10 GHz. The 7-cell screen then transmits mostly by tunnelling.
- In the screenshot the field in front of the screen is a standing wave at +-1.66 a.u. (this also sets the auto-range). Hover at x = 294 mm reads 0.53 a.u.
- The physics is correct, but the preset shows cutoff and reflection rather than two-slit interference.
- Fix: openings of 1-1.5 lambda (30-45 cells) with a centre spacing of about 3 lambda, or say "slits at cutoff" in the tooltip.

**M2. The colorbar hides clipping and has no log option.**
- Auto-range at the 99th percentile clips, and so does the fixed LBM vorticity range of +-100 1/s, which saturates at the cylinder. Nothing marks out-of-range values.
- There is no log toggle (guideline "log toggles") for E_z^2 or |u|.
- The Gray-Scott unit label "1" under the bar reads as a tick.
- Fix: end caps or an out-of-range marker; a log toggle for non-negative views; unit text "dimensionless" or "[1]".

**M3. Native checkboxes draw rounded corners.**
- Computed `border-radius` is 0 on every element (verified).
- Native checkboxes ("auto range", "smooth") still render rounded at 3x.
- Fix: `appearance: none` with a square custom box.

**M4. A favicon 404 appears in every Chrome run.**
- "Failed to load resource ... 404" is in every `logs/rt-chrome-*.json` and in this audit's run.
- Fix: `<link rel="icon" href="data:,">`.

**M5. The C9 changelog item `lengthUnit` is not implemented.**
- The contracts changelog (2026-11-06 15:5x) adopted an optional `grid.lengthUnit`. `src/types.ts` `Grid` lacks it.
- The Gray-Scott hover prints an empty unit ("x 3.67 y 4 ").
- Fix: add `lengthUnit?: "m" | "model"` and print "model units".

**M6. The LBM force-link list truncates silently.**
- `rebuildLinks()` caps the links at nx*ny entries (`out.length = cap`). Thin painted structures can exceed this (up to 8 links per fluid cell), and the force integral is then wrong without warning.
- Fix: size the buffer at 8 N, or report `truncated` in `info()` and in the UI.

**M7. The MIT notice is not carried with the demo.**
- `demo/lib/colormaps.js` holds the cmocean (MIT) table. Its header names the copyright but only points to `packages/rt/NOTICE`. If `demo/` is deployed on its own, the MIT permission text is not shipped.
- `NOTICE` mentions only `src/colormaps.ts`.
- Fix: emit `NOTICE` into `demo/` (or inline the MIT text in the colormaps header) and list the generated copy.

**M8. Citation and description of the outlet.**
- DevLog-005 s.8 "Guo, Zheng and Shi 2002 (forcing; non-equilibrium extrapolation)" merges two papers: Phys. Rev. E 65, 046308 (forcing) and Chinese Physics 11, 366 (NEE boundary).
- The implemented outlet is a variant (outlet-column post-collision non-equilibrium part along the link, unknown populations only). Results are equivalent (section 2).
- Fix: cite both papers and describe the variant in L6-3b.

**M9. Bandwidth note in s.6.4.**
- "Exceeds DRAM bandwidth" gives no figure and no source. The traffic estimate is also low: 9 x 4 B read + 9 x 4 B written + 4 B mask + 12 B macroscopic fields = 88 B/cell/step, not 84.
- Fix: cite Apple's M4 Pro memory-bandwidth specification (to be verified and cited by the lane, not by this audit), and use 88 B.

**M10. The demo loop has no GPU back-pressure.**
- `frame()` encodes `spf` steps on every animation frame whether or not earlier work has finished. The "steps/s" status counts encoded steps, not completed ones. On a slower GPU the queue grows and so does input latency.
- On this machine 60 fps is sustained (section 1), so this is not visible here.
- Fix: skip stepping while the previous frame's `onSubmittedWorkDone()` is pending, and count completed steps.

**M11. Hover re-runs the view kernel.**
- `hover()` calls `S.k.view()` only to get the buffer, which re-dispatches the view kernel and rewrites its uniform on every hover sample.
- Fix: cache the buffer returned at bind time.

**M12. The share URL is not the full spec.**
- Painted geometry is not encoded (O4). The guideline asks for share-by-URL that holds the full spec. Known and tracked.

**M13. FDTD field amplitudes are in a.u.**
- The soft source adds `srcAmp` to Ez each step, so field amplitudes are a.u. The labels say so, honestly, but the guideline asks for absolute units.
- Fix: inject a current density J_z [A/m^2] (Ez -= dt J/(eps0 eps_r)), so Ez is in V/m and |H| in A/m.

## 5. f32 precision on the GPU

- Handled well:
  - LBM populations are stored as deviations. The auditor's full-f f32 control is 1.7x-37x worse (section 2).
  - Time, source waveform and force/lift time series are kept in f64 on the host.
  - Gate tolerances are set against f32 references: Gray-Scott is compared with an operation-by-operation `Math.fround` mirror.
  - GPU-vs-CPU agreement: FDTD 2.0e-7; LBM 5.8e-6 (u_x), 1.5e-5 (u_y), 2.9e-6 (rho); dispersion 3.4e-8.
- Effect on gates:
  - None on St, CPML (-91.4 dB on both CPU and GPU), the cavity (GPU = CPU to 1e-9) or the pattern class.
  - The TRT Poiseuille floor of about 2-4e-5 on the GPU is f32 round-off. It does not fall with H. [est] The rounding bias per step accumulates over the H^2/nu relaxation time.
  - Gray-Scott is not bit-identical to the f32 mirror (1e-5 after 1000 steps). FMA contraction is a plausible cause, as DevLog-005 marks with [est].
- [est] The force kernel adds w_k to g_k in f32 before the reduction. This costs about 7 bits per term, about 1e-7 relative on c_D. Immaterial; summing g only would avoid it.
