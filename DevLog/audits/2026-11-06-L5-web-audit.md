## 2. Findings

### Blocking

**B1. Play shows a result for the previous parameter value, labelled fresh, after an exact-field commit of a non-geometry parameter; undo, redo and presets on such parameters never re-solve.**
- Evidence (helmholtz Play, 1440 px): typed I = 2 A in the exact field and pressed Enter. After 2.5 s: `params.I = 2 A`, `W_m = 7.389e-7 J` (the I = 1 A value; W_m scales with I^2, so 2.956e-6 J is expected), `staleSolution = false`, no stale marker anywhere. Undo back to 1 A: no re-solve, footer "solution stale", aside scalars unmarked.
- Rib after the rebuild: after a lambda0 drag and Undo the canvas and aside show the lambda0 = 2.05 um modes (neff_0 3.396, substrate-leaky) next to the slider at 1.15 um; only the footer says "solution stale" (`logs/audit-l5-play-rib-stale-1440-20261106T163923.png`).
- Cause: `ParamSlider` calls `onpreview(v); ondragend()` and `oncommit(v)` calls `stepParam(p, v); s?.finishDrag()` (`lib/play/Play.svelte`), where `stepParam` fires `void s.model.dragStep(...)` without awaiting it. `finishDrag` -> `scheduleMesh(1)` -> `compute()` reads `model.text` before `log.apply` has landed. For geometry params, `onEdit` reschedules a mesh when the op lands, so the error heals. For solution-only params (I, lambda0, sigma_inf, frequencies) nothing reschedules, and the late result clears `staleSolution`. `Session.onEdit` never recomputes on a `solution`-only invalidation, and Play has no Compute button.
- Fix: await the op before `finishDrag` (make `stepParam` return the promise). With `autoCompute`, run `compute()` on every op that invalidates `solution` (coalesced, one in flight, latest wins). Tag every Solution with the spec hash it was computed from (`op.after`) and draw or list it only when that hash equals the current one. Otherwise show it dimmed with "stale", aside scalars included.

**B2. At 390 px the workbench "log" pane covers the pane switcher, and the user cannot leave it without reloading.**
- Evidence: after tapping "log", `elementFromPoint` at the centre of each of the four switcher buttons (y = 78 px) returns the bottom panel, not the button. `.bottom.mshow` is `position: fixed; top: 76px`, while the wrapped toolbar plus switcher is about 100 px tall (`logs/audit-l5-wb-390-log-trap-20261106T163923.png`).
- Fix: do not use a fixed offset. Put the bottom pane in the same grid cell as the other panes (row 2 of `.wb`), or compute `top` from the toolbar's measured height.

### Significant

**S1. After a run that ends "unavailable", the previous field is still drawn.** Workbench, kirsch: Compute with the case on (solved), then the case unchecked and Compute run again. The status reads "results unavailable", Messages (4) shows `material 'steel' has no value for 'E'`, and the Results tree items are greyed, yet the canvas still draws the old sxx map with an MPa colorbar. The only hint is "solution stale" in the footer (`logs/audit-l5-wb-nocase-stale-field-1440-20261106T163923.png`). `Graphics.svelte` treats results as unavailable only when `!sol`, and `sol` only checks `meshHash`. Fix: on `unavailable` or `error`, drop or dim the solution. Key the solution on spec hash plus run options (case flag), not on the mesh hash alone.

**S2. The material provenance display credits the eval case in heroes where the case supplied nothing.** All six Play views show a checked "materials from eval case X" box with a tooltip listing the case values. Node `prepareRun` on the same specs: heat (k = 52 in the spec), helmholtz (mu_r override), rib (n = 3.44/3.40/1 in the spec after 16:40), box, cavity -> `notes: []`, so no value came from the case. Only kirsch uses the case: SM-01 `E 200 GPa, nu 0.3, source: synthetic (stresses independent of E, nu)`, because `materials/structural-steel` E and nu need a temperature. Even there, u_max = 5.20e-7 m and the u field rest on a synthetic E, and the Play results list shows them with no marker. In the 16:39 build the rib run reported `material 'core': n is N/A` while the same toolbar tooltip claimed `core: n 3.44` from WO-02. Fix: build the label from `prepareRun` notes (list the properties actually filled, or "case: none used"). Put a provenance marker on every scalar or field that depends on a case-filled value. Delete `SIM_CASE` once the I1 spec links land (CONTRACTS changelog 16:38).

**S3. The browser and Node meshes differ for the same kirsch spec, so the field the user sees is not the one the eval harness gates.** The exact browser spec text was run through `@amp/physics` in Node (SM-01 case):

| Quantity | Browser (post-worker probe) | Node (`@amp/post` sample) |
|---|---|---|
| mesh | 2632 tri6, hash `072091b7` | 2635 tri6, hash `81aad861` |
| DOF | 10,764 | 10,766 |
| sxx at (0, 5 mm) | 3.016601 MPa | 3.021246 MPa (0.15 % apart) |
| sxx at (20, 20) mm | 1.035873 MPa | 1.035363 MPa |
| mises_max | 3.018306 MPa | 3.021095 MPa |

Heat and helmholtz match exactly: identical mesh hashes `cf0eb80f` and `e1d4d9dc`. T(0.6 m, 0.2 m) = 291.403761 K (18.25 degC) in both, and Bz(0, 0) = 8.983028 uT in both. The probe returns exactly the engine's FE value, and the colorbar units are right (MPa, degC, uT). Cause not identified: `packages/mesh/src` has no time or random dependence (only `performance.now` for stats). Candidates are V8 `Math.*` differences between Chrome 151 and Node 23.7 on the curved-boundary discretization, or bundling. Fix (L3 + L5): a browser-vs-Node mesh-hash test for every hero in the shots script, the mesh hash shown in the UI footer tooltip, and the hash recorded in the run record.

**S4. Eigenmode amplitudes are shown in absolute units.** Box mode 172 Hz: colorbar "Pa", ±703 Pa. Rib normE: "V/m", 0 to 0.80 (normalized to max 1). These are normalizations, not physical amplitudes; L4 request 4d is still open. Fix: until the Solution states its normalization, label eigen fields "normalized, arb. units" and drop the unit, or normalize to a stated physical quantity (the rib already reports `powerW_k`).

**S5. The 1st-99th percentile range is taken over the whole domain, so the hero quantity saturates.** Kirsch Play colors 0.901-1.10 MPa while the story is the K_t = 3 peak (3.02 MPa), shown as a saturated yellow blob. Helmholtz Bz uses ±4.75 uT while Bz at the centre is 8.98 uT, so the entire uniform region (the point of H3) is saturated dark red (`logs/audit-l5-play-kirsch-p99-1440-...png`, `...-helmholtz-p99-...png`). The labelling is honest (colorbar "p1-99"), but the default view hides the physics. In the workbench, the full-range symmetric diverging map (±3.02 MPa for sxx with a minimum of -65 kPa) leaves half the map unused. Fix: compute the percentile over the visible focus box, mark the peak (value and location), and use a sequential map when the negative part is under about 5 % of the range.

**S6. Long main-thread tasks.** Kirsch Play: 355 ms and 573 ms tasks after the drag-end solve (first build). Rib: 268 ms and 603 ms. Workbench load: 602 ms. Box drag: 18 tasks of 58-79 ms during a 12-step drag. Gray-Scott load: 1.34 s. These break the "drag-to-repaint < 100 ms" feel (DevLog-001 s.4). The cause was not profiled. Candidates are the main-thread lattice, percentile sort and 3D attribute builds in the `$derived` blocks of `Graphics.svelte`. Fix: profile, and move the lattice, percentile and exterior or attribute builds to the post worker, transferring typed arrays.

**S7. No live feedback while dragging a non-geometry parameter.** For lambda0 (rib), `dragMs` stays "-": the field does not change during the drag, then a 3.9-4.7 s full solve runs on release with no progress bar. Coarse re-solve only runs on geometry or mesh invalidation. Fix: a coarse re-solve (`meshScale` 2) for solution-only params too, a "coarse" badge, and a progress bar for solves over 1 s.

**S9. No log toggle anywhere.** s.6 asks for log toggles. `renderer2d` and `Colorbar` support `log` and `symlog`, but `Graphics.svelte` never exposes them. Fix: add a lin/log/symlog control next to p1-99.

**S10. Security: the agent slot is not ready for a BYO key.**
- No `Content-Security-Policy` in `_headers` and no `kit.csp`. The build has one inline bootstrap `<script>`.
- `window.__ampWorkbench` and `window.__ampPlay` expose the session in production builds.
- The op log takes the actor from the caller. I appended an op with `actor: 'agent:audit'` through `session.model.log.apply` (private only in TypeScript); the agent-reason rule held: `agent operations require a reason`.
- Positives: no `{@html}`, `innerHTML`, `eval` or `new Function` in `src/`. A share link that sets the title to `<img src=x onerror=...>` renders as text and does not execute. The only external URLs in the bundle are citation strings in the materials data. The service worker serves same-origin GET only.
- `_headers` is valid Cloudflare Pages syntax. When parsed and applied, it gives `crossOriginIsolated = true`. It is not yet exercised on Cloudflare itself.
- Fix before L9 mounts:
  - `kit.csp` in hash mode with `default-src 'self'`, `script-src 'self'` plus hashes, `connect-src 'self' <provider origin>`, `img-src 'self' blob: data:`, `worker-src 'self' blob:`.
  - Keep the key in memory or in an opt-in store kept out of the spec, op log, share URL, JSONL export and screenshots.
  - Strip the `__amp*` hooks in production, or gate them behind a dev flag.
  - Add `ModelState.applyAgent(session, patch, reason)` that binds the actor, and refuse caller-provided actors.

## 3. Visual quality and the R5 lessons

Ratings are my judgement against s.6 and R5 s.2:

| View | Rating /10 | Notes |
|---|---|---|
| RT panels | 7 | Closest to "gorgeous": LBM vortex street, FDTD rings and Gray-Scott spots are crisp; diverging maps; fidelity notes |
| Workbench | 6 | Proper COMSOL structure (tree, Settings/YAML, Graphics, bottom tabs), dense, sharp. Large empty areas at 1440 px (Settings below 3 params, a 170 px "No messages." panel). Results open on the whole plate, where the concentration is a few pixels |
| Play 2D (kirsch, heat, helmholtz, rib) | 5 | Smooth lattice rendering, but the default ranges hide the physics (S5). No field lines for the coil (R5 lesson 6). No headline number (K_t, B uniformity) |
| Play 3D (box, cavity) | 4 | Unlit flat-shaded surfaces, no edges or outline; faceted 16-gon cylinder in flat region blue; mode phase animation off by default |

Not yet "gorgeous": the data story is not visible at first glance in 4 of 6 Play views.

Top 10 improvements, one line each:
1. Auto colour range over the visible region, plus a peak marker with its value (K_t = 3.02 at the hole top).
2. Show the spec's headline result (kt, B_center, f_1, neff) large in the corner, in its spec unit, recomputed live.
3. Field lines and streamlines (coil B, LBM velocity) and contour overlay on by default in Play (R5 lessons 5-6).
4. 3D shading: normal-based lighting, silhouette edges and a subtle ground plane; smooth curved tet10 faces.
5. Eigen modes: the phase animation starts on the first interaction, and a frequency list in the aside selects the mode on click.
6. Live coarse feedback for every slider, with a "coarse" badge, and a thin progress bar for runs over 1 s.
7. Engineering prefixes and proper symbols (MPa, GHz, uT -> µT, degC -> °C) everywhere; no trailing "1".
8. Timeline: coloured actor badges (user / agent:<id>), an actor filter, hover diff; reverts refused inline (already present).
9. Mobile: 40 px controls, parameters in a bottom sheet, horizontal colorbar, a canvas that fills the width.
10. Move the lattice, percentile and 3D attribute builds to the post worker so no main-thread task exceeds 50 ms.
